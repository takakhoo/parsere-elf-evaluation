\begin{abstract}
Reverse engineers who already understand the input format a binary parses spend most of their initial effort locating the code that implements each piece of the format.
We present \toolname, a binary-only tool that automates that step.
Given a grammar template for the input format, \toolname instantiates a corpus of structurally varied inputs, traces each one under \QEMU user-mode emulation, compares pairs of traces whose parse trees differ in exactly one production, and attributes the differential basic blocks to that production.
A two-step uniqueness filter removes shared code, and the result is a labeled control-flow graph in which most parser-relevant basic blocks carry the name of the grammar rule they implement.
Unlike prior approaches, \toolname requires no source code, no compiler instrumentation, and no data-flow analysis.
We evaluate on parsers for four formats spanning the language hierarchy: URI (regular), JSON (context-free), HPACK (context-sensitive binary), and ELF (offset-driven binary).
On the completed ELF evaluation against libelf, manual inspection of every label yields 91.2\% strict accuracy across 68 labeled basic blocks.

\end{abstract}

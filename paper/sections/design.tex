\section{Design}\label{sec:design}

\toolname is designed to associate input grammar elements with the program regions that process them.
Our approach rests on the hypothesis that parsing routines are structured such that distinct grammar constructs are handled by distinct regions of the control-flow graph.

Figure~\ref{fig:overview} sketches the pipeline.
The four phases are: (1)~corpus generation from a grammar template, (2)~execution tracing under \QEMU, (3)~associating parse-tree deltas with trace deltas, and (4)~a uniqueness filter that distills the per-production labels.

\subsection{Corpus Generation from Templates}\label{sec:design:corpus}

\toolname begins with a grammar template: a tree of production rules where each leaf offers a small set of byte-level alternatives, and each internal node offers a set of child configurations.
Given a template, \toolname enumerates every combination of alternatives, yielding a corpus of concrete inputs each paired with its parse tree.

The templates are deliberately small.
For JSON, the template generates inputs containing objects, arrays, strings, numbers, booleans, and null values in various combinations.
For URI, it generates URIs with varying schemes, authorities, paths, queries, and fragments.
The key property is that every pair of instantiations differs in exactly one or a small number of grammar productions, which enables clean attribution.

\subsection{Execution Tracing}\label{sec:design:trace}

Each input in the corpus is fed to the target binary, which runs under \QEMU in user-mode emulation.
\QEMU logs every basic block it translates, producing a trace file for each input.
\toolname parses each trace into an ordered sequence of basic blocks and retains only blocks within the target's executable segment.
Blocks from the dynamic linker and \QEMU runtime are discarded.

For each input, the trace becomes a block trace (the sequence of basic blocks visited) and an edge map (the set of consecutive basic-block pairs observed).
The edge map is the primary representation we use for differential analysis.

\subsection{Associating Labels to Trace Deltas}\label{sec:design:assoc}

For each pair of inputs whose parse trees differ in exactly one production, \toolname computes the \textbf{edge delta}: the set of edges present in one trace but not the other.
The differing production label is then associated with those edges.

Formally, let $T_i$ and $T_j$ be two inputs whose parse trees differ only in production $p$.
Let $E_i$ and $E_j$ be their edge maps.
The edges $E_i \setminus E_j$ are attributed to production $p$.
Aggregating over all input pairs that isolate $p$ yields a set of edges associated with $p$.

\subsection{Uniqueness Filter}\label{sec:design:unique}

Raw edge-to-label associations are noisy.
Many edges are shared across productions, for example error-handling code that runs for any malformed input.
\toolname applies a two-step filter to clean the associations.

\begin{enumerate}
    \item \textbf{Subset removal.} If the edge set for production $p_1$ is nearly a subset of the edge set for $p_2$ ($|p_1 \setminus p_2| / |p_1| < 0.1$), we remove $p_1$'s edges from $p_2$'s set. This eliminates noise from shared setup and teardown code.
    \item \textbf{Strict uniqueness.} For each production, we subtract the edges attributed to every other production. Only edges attributable to a single production receive a label.
\end{enumerate}

After filtering, \toolname propagates colors backward through the CFG.
If every outgoing edge of a node carries the same label, the node itself receives that label.
This captures basic blocks that are the sole entry point to a production-specific subgraph.

\subsection{Output}\label{sec:design:output}

The final output is a graph with colored edges and nodes, rendered for visual inspection.
\toolname also emits an address-to-label mapping that an analyst can import into a disassembler.
A companion Ghidra script attaches per-block annotations to the disassembly listing, which lets the analyst inspect the labeling directly inside the reverse-engineering workflow.
